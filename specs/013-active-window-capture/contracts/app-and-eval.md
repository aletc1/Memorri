# App and eval contracts: window capture

## Shortcut

| Item | Contract |
|---|---|
| Name | `captureWindow`, default Control+Option+Command+W |
| Actions | `capture`, `window`, `search`; labels "Capture now", "Capture window", "Search" in refusal messages |
| Check | each recorded shortcut is validated against every other action and against `CopySymbolicHotKeys`; a refusal reverts to the previous shortcut (existing messages, with the other action's label) |
| First run | if the user's saved capture or search shortcut already equals the default, the window shortcut starts unassigned and Settings says why |
| Press | `captureService.requestWindow(.shortcut)` |

## Menu and Settings

- Menu: "Capture window" below "Capture now", with the shortcut shown in the title as for "Capture now"; calls `requestWindow(.menu)`.
- Settings, shortcut section: a third `Recorder` row "Capture window shortcut:" with "Reset to default" and the red rejection text, like the other two.
- Last-capture line: `Last window capture: <app>, <age>`; failure and warning lines as for full-screen captures; "no window to capture" and "Memorri's own windows are not captured" are the two new reasons.

## The red outline (App)

| Property | Value |
|---|---|
| Window | one borderless, non-activating panel per display the frame touches |
| Input | `ignoresMouseEvents = true`, never key or main |
| Level and Spaces | above the menu bar and full-screen windows; all Spaces; full-screen auxiliary |
| Capture | `sharingType = .none`; created after the picture is stored |
| Look | red stroke, 4 points, inside the recorded rectangle; shown for about 1 s, then fades over about 0.25 s |
| When | only after a stored successful window capture; never on failure, refusal or "no window" |

## Eval

`meta.json` gains an optional `scope` (`"displays"` default, `"window"`). For `"window"` the screenshot is the window picture, `windows` holds that one window with a frame covering the picture and `stack` 0, and `displaySize` is the picture size.

New synthetic cases (generated by `memorri-eval generate-synthetic`, files tracked like the others):

| Case | Shows | Expected |
|---|---|---|
| `window-capture-mail` | a mail alone, no menu bar | items from the mail, dates from its headers, no guess flag from a missing clock |
| `window-capture-month-other-month` | a month grid on a month other than the capture's, no title bar clock | entries in the month shown, no model extraction call |
| `window-capture-remote-clock` | a remote window with its own taskbar clock in another time zone | relative dates against that clock |
| `window-capture-covered` | a calendar with a small panel drawn over a corner | entries outside the panel found; nothing taken from the panel |
| `window-capture-terminal` | a terminal window | no findings, no error |

`memorri-eval run` reports the per-case scores. Acceptance: the 33 existing cases score as before (no case loses more than 0.02) and model calls for them do not change; the new cases score 1.00 on dates and kinds as in the spec 011 window cases.

Debug builds: `--ingest-case <folder>` reads `scope` from `meta.json` and stores the picture as a window capture.
